# 同一端口同时提供 HTTP 和 HTTPS

默认配置下，`-addr` 这一个端口同时接受 HTTP 和 HTTPS。用 `https://` 打开时，单聊可以语音、视频和共享屏幕。用 `http://` 打开时，可以聊天、传文件和使用后台，没有这三项。

本设计替换《一对一 WebRTC 通话设计》里「服务默认在原来的 `-addr` 上提供 HTTPS，不再在该端口提供 HTTP」。`-tls=false` 的行为不改。

## 端口

不新增依赖，不新增端口，不新增命令行参数。

`cfg.TLS` 为真时，进程在 `-addr` 上接受 TCP。每条连接先读第一个字节，再把这个字节交回给后续处理：

- 第一个字节是 `0x16`：按 TLS 处理，使用现有自签证书。
- 其他字节：按 HTTP 处理。
- 读失败或没有字节：关闭这条连接。

证书、TURN 和通话会话的创建条件仍是 `cfg.TLS`。TURN 继续使用同一端口号的 UDP。桌面程序不传 `-tls=false`。

`-tls=false` 时进程只提供 HTTP，不生成证书，不监听 TURN，不创建通话和屏幕共享会话。`GET /api/features` 返回 `{"calls": false}`。

`cfg.TLS` 为真时，HTTP 和 HTTPS 请求的 `GET /api/features` 都返回 `{"calls": true}`。不新增字段。页面用自己的协议决定按钮，不靠这个接口区分。

## 页面

按钮和信令处理看 `location.protocol === 'https:'`，不再只看 `window.isSecureContext`。`http://127.0.0.1` 和 `http://localhost` 在浏览器里是安全上下文，这两项在这里仍然没有语音、视频和屏幕共享。

`https://` 页面保持现在的单聊语音、视频和屏幕共享。

`http://` 页面：

- 不显示语音、视频、共享屏幕。
- 不发出这些请求。
- 收到 `call.*` 或 `screen.*` 时忽略，不打开浮层。

聊天、文件、好友、群和后台在两种页面上都能用。WebSocket 继续按页面协议选择 `wss:` 或 `ws:`。

## 服务对信令的处理

聊天消息仍发到该用户的每条 WebSocket，不论这条连接是不是 TLS。

通话和屏幕共享另算在线：对方至少有一条经 TLS 接受的 WebSocket，才算在线。只有 HTTP 连接时，邀请得到现有的离线结果，不进入 30 秒等待。通话和屏幕共享的投递只写到这些 TLS 连接。

一条不是 TLS 的 WebSocket 如果发来 `call.*`，连接上得到「通话不可用」，会话不接受这次请求。`screen.*` 得到「屏幕共享不可用」。

某条 WebSocket 关闭时，通话和屏幕共享仍按现在的规则结束：这一侧的会话通知另一侧，即使该用户还有别的页面连着。HTTP 页面关掉时也一样。

## 地址

`cfg.TLS` 为真时，启动输出对每个主机先写 HTTPS，再写 HTTP。主机顺序仍是 `127.0.0.1`，然后是局域网 IPv4。每个主机四行：

```text
https://127.0.0.1:8080/
https://127.0.0.1:8080/admin
http://127.0.0.1:8080/
http://127.0.0.1:8080/admin
```

账号和密码两行仍在全部地址之后。`-tls=false` 时仍只写 `http://`。

桌面程序的访问地址分成聊天和后台两组。每一组里，对每个局域网 IPv4 先列 `https://`，再列 `http://`。本机回环地址仍不放进这份列表。「打开聊天」和「打开后台」仍打开 `https://127.0.0.1:<端口>`。判断服务是否在监听仍用 HTTPS 请求本机。
