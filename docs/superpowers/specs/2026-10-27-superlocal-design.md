# SuperLocal 设计

第一版是一个 Web 版局域网传输工具。一台机器运行主服务，其他设备用浏览器登录、一对一聊天、建群、发文字、发图片、发文件。屏幕共享、远程控制和程序内置 HTTPS 不在这一版。

## 运行形态

一个 Go 进程同时提供聊天页、管理后台、HTTP API 和 WebSocket。监听 `0.0.0.0:8080`，可用启动参数修改。Vue 3 的构建结果通过 `go:embed` 打进同一个二进制。

数据目录默认是进程当前目录下的 `data/`，可用启动参数修改。其中包含：

- SQLite 数据库
- 上传文件和头像
- 管理员凭证文件 `admin.secret`，文件权限 `0600`

启动参数：

- `-addr`，默认 `:8080`
- `-data`，默认 `./data`
- `-max-upload`，默认 `200MB`

消息保留时间和清理间隔固定为 48 小时，第一版不做成配置项。

进程使用纯 Go 的 SQLite 驱动，不依赖 CGO。数据库使用 WAL。

### 启动输出

终端打印：

- `127.0.0.1` 和每块网卡上的 IPv4 地址
- 聊天页 `http://<ip>:<port>/`
- 管理后台 `http://<ip>:<port>/admin`
- 管理员账号和当前密码

密码同时写入 `admin.secret` 和数据库中的口令哈希。管理员在后台修改密码后，文件和哈希一起更新，当前管理会话保持有效。下次启动打印新密码。

若数据库里已有管理员哈希，但 `admin.secret` 丢失，启动时生成新密码并同时替换文件和哈希，保证终端始终能打印当前密码。

### 公网

程序只提供 HTTP。公网访问时由反向代理或端口映射终止 TLS，WebSocket 使用同一域名。

## 技术划分

| 部分 | 职责 |
| --- | --- |
| `cmd/superlocal` | 启动、打印地址和账密、挂接清理任务 |
| `internal/store` | SQLite 读写 |
| `internal/auth` | Key 登录、管理员登录、会话、限流 |
| `internal/chat` | 一对一、群、消息 |
| `internal/files` | 上传、下载、头像 |
| `internal/hub` | WebSocket 连接和在线状态 |
| `internal/admin` | 统计、封禁、权限、解散群 |
| `web` | Vue 3 单页应用 |

前端使用 Vue 3、Vue Router、Pinia、Axios、Vite。管理页使用 Element Plus。聊天页单独做界面，不使用后台组件库。样式使用 UnoCSS。不引入内部 npm 包。

聊天页和管理页是同一个前端应用的两套路由。聊天用户的 Cookie 不能访问管理接口。

## 界面

产品名显示为 SuperLocal。布局和密度参照飞鸽传书的桌面客户端：左侧切换「消息」和「联系人」，中间是列表，右侧是聊天。视觉做成商业桌面软件，紧凑、对齐、少装饰。不使用插画、大圆角、渐变色块和卡通空状态。

桌面优先。视口宽度小于 960px 时，列表和聊天分成两屏，从列表进入聊天，聊天页提供返回。

### 色彩和密度

全站共用这些颜色：

- 主色 `#0B6BCB`，按下 `#0958A8`
- 页面底 `#F3F5F7`
- 面板 `#FFFFFF`
- 分割线和边框 `#E6E8EB`
- 主文字 `#1F2329`
- 次文字 `#646A73`
- 在线 `#22A06B`
- 自己的文字气泡用主色配白字，对方气泡 `#F2F3F5` 配主文字

正文字号 14px，辅助信息 12px。面板圆角 8px，头像圆形 36px。应用外壳可以有一层很轻的阴影，列表和气泡不再叠加阴影。字体使用 `PingFang SC`、`Microsoft YaHei`、`sans-serif`。

### 登录

页面居中一张白卡片，放在浅灰背景上。卡片内是产品名、一行说明「用 Key 进入，Key 即账号」、Key、首次登录的昵称、进入按钮。校验错误显示在字段下方。

### 聊天

顶部一条白栏：自己的头像、昵称、在线状态，右侧进入个人资料。个人资料里显示自己的 Key（只读），并可修改昵称和头像。列表、聊天标题、气泡和建群选择器只显示昵称和头像，不显示别人的 Key。昵称重复时也不显示对方 Key。

左侧竖条只有两个入口：「消息」「联系人」。中间栏顶部是搜索框。

- 「消息」列出这两天内有消息的一对一和群。每行是头像、名称、最后一条摘要、时间。有未读时在右侧显示数字。点开会话后未读清零。离线对方的头像变为灰色，名称旁保留离线字样。
- 「联系人」只列出当前在线用户。点击某人打开一对一。栏顶有「建群」按钮，打开对话框填写群名，并按昵称搜索已注册且未封禁的用户进行多选。没有建群权限时不显示该按钮。列表搜索只过滤当前栏里的会话或在线用户。

右侧聊天区顶部是对方昵称或群名，以及在线、离线或人数。中部是消息，从旧到新。文字用气泡。图片在气泡内预览，宽度不超过 320px。文件是一条横条：类型图标、文件名、大小、下载。自己的消息靠右，对方的靠左，上方显示发送者昵称和时间。

底部是输入区。工具栏有「图片」和「文件」。文字框最多显示 4 行，Enter 发送，Shift+Enter 换行。输入法正在组字时，Enter 不发送。主按钮文案是「发送」。可以把文件拖到聊天区或联系人头像上，松手后按文件规则上传并发送。群拖到该群所在的列表行上。

空列表和空聊天用一行次文字说明，不用大插画。

### 管理后台

同一套主色和字号。左侧导航宽 200px，三项为「概览」「用户」「群」。右侧白底内容区。概览是同一行的五张数字卡。表格使用 Element Plus 的紧凑尺寸，表头用次文字，操作是开关和文字按钮。登录页与聊天登录页同一卡片样式，字段为账号和密码。

## 账号

### 聊天用户

用户用自己填写的 Key 登录，没有密码。Key 去掉首尾空格，长度 8–64，字符只允许字母、数字、`-` 和 `_`。

第一次出现的 Key 创建账号。已经存在的 Key 直接进入该账号。知道 Key 的人就是该用户。登录页写明这一点。

同一 Key 可以同时打开多个浏览器。任一连接仍在，该用户就显示在线。

昵称长度 1–32，不含换行。首次登录必须填写。已有账号再次登录时不修改昵称。登录后可以在个人资料里修改昵称和头像。

`GET /api/me` 返回自己的 Key，以及 `canSendMessage`、`canSendFile`、`canCreateGroup` 三项权限，供页面禁用对应控件。其他聊天接口、在线列表、用户搜索、会话、消息和 WebSocket 事件只返回用户编号、昵称、头像和在线状态，不返回别人的 Key。管理接口仍然返回 Key，供后台查看和搜索。

头像是 JPEG、PNG、WebP 或 GIF，最大 2MB。头像不参与 48 小时清理。

登录接口按 IP 计数，每分钟最多 20 次。超出后提示稍后再试。

会话 Cookie 名为 `sl_session`，HttpOnly，有效期 7 天。WebSocket 使用这枚 Cookie。

### 管理员

管理员账号与聊天用户分开，不能用来聊天。首次启动创建用户名 `admin` 和 16 位随机密码，字符为大小写字母和数字。

管理会话 Cookie 名为 `sl_admin`，HttpOnly，`SameSite=Lax`，有效期 7 天。聊天会话 Cookie 同样使用 `SameSite=Lax`。账密错误时只提示登录失败。

### 权限

每个聊天用户有四项状态，新用户默认允许发言、发文件和建群：

- 封禁
- 允许发言
- 允许发图片和文件
- 允许建群

管理员可以立即切换这些状态。封禁会断开该用户的全部连接，该 Key 不能再登录。后台不能修改 Key。

## 会话和消息

### 一对一

在线列表只显示当前有 WebSocket 连接的用户。点击在线用户时，服务器为这两人查找或创建一个一对一会话。同一对用户只有一个一对一会话。第一条消息写入后，该会话才出现在会话列表里。

对方后来离线时，已有消息的会话仍留在列表中。消息过期并被清理后，列表不再显示这个没有消息的会话。对方已被封禁时，不能再向该一对一会话发送。

每个成员在会话上记录最后读到的消息编号。未读数等于此后、且不是自己发送的消息数。打开该会话时更新最后阅读编号。

### 群

有建群权限的用户创建群。群名长度 1–40。创建时除创建者外至少再选 1 名已注册用户。成员选择器按昵称搜索已注册且未封禁的用户。

创建者可以继续添加未封禁的成员，不能把别人移出。任何成员可以退出。创建者退出后群继续存在。第一版没有群主转让。

后加入的成员可以看到该群仍在保留期内的消息。退出后，该群从自己的会话列表消失，也不能再下载其中的文件。

管理员可以解散群。解散时删除成员关系，成员的会话列表中不再显示该群，也不能再下载其中的文件。保留期内的消息和文件等到清理任务删除。

### 消息

消息属于一个会话，类型为文字、图片或文件。

- 文字最长 4000 字
- 图片和文件先上传，再发送一条引用该文件的消息
- 单个文件默认最大 200MB
- MIME 属于 `image/jpeg`、`image/png`、`image/webp`、`image/gif` 的文件按图片消息发送，聊天中直接预览
- 其他类型按文件消息发送，显示文件名和大小，并提供下载

下载必须带 `sl_session`。服务器只把文件发给仍是该会话成员的用户。不是成员的用户不能向该会话发消息。

### 保留和清理

消息和对应文件保存 48 小时。用户、群成员关系、头像不按这个周期删除。

启动时先删除已经超过 48 小时的消息、对应文件，以及没有被消息引用且超过 48 小时的临时文件。此后每 48 小时再执行一次。刚清理完就发出的消息会留到下一次清理，最长接近 4 天。

上传失败时立即删除这次的临时文件。

## 实时传递

登录成功后建立一条 WebSocket。断开后按 1 秒、2 秒、4 秒重连，间隔上限 15 秒。消息编号使用按时间递增的 ULID。重连后，客户端对每个已打开的会话调用 `GET /api/conversations/:id/messages?after=`，补齐编号更大的消息。

文字经 WebSocket 发送。图片和文件先经 HTTP 上传，成功后再发送带文件编号的消息。服务器确认后，把消息推送给会话中当前在线的成员，包括发送者。

用户被封禁、失去发言权或失去发文件权时，服务器拒绝对应操作，只通知发送方。失败的内容不会成为消息。

服务重启后，页面自动重连。历史从数据库补齐。在线状态以新连接为准。

客户端发往服务器的事件：

- `message.send`：`conversationId`、`kind`，以及文字或文件编号

服务器发往客户端的事件：

- `message.new`
- `presence`
- `error`
- `session.revoked`：被封禁时断开前发送

## 管理后台

`/admin` 使用独立登录。

概览显示：注册用户数、当前在线数、封禁人数、保留期内的消息数、保留期内文件占用的磁盘空间。

用户表显示昵称、Key、在线或离线、最近在线时间、发言、发文件、建群、封禁状态。可按昵称或 Key 搜索。

群表显示群名、人数、创建时间。管理员可以解散群。

## 接口

聊天用户：

- `POST /api/session`：提交 `key`、首次登录的 `nickname`
- `POST /api/logout`
- `GET /api/me`
- `PATCH /api/me`：修改昵称
- `POST /api/me/avatar`
- `GET /api/users/online`
- `GET /api/users?q=`：建群时搜索未封禁用户，最多返回 50 人
- `POST /api/conversations/direct`：按对方用户编号打开一对一
- `GET /api/conversations`
- `POST /api/groups`
- `POST /api/groups/:id/members`
- `POST /api/groups/:id/leave`
- `GET /api/conversations/:id/messages?after=`：`after` 为最后一条消息的 ULID，省略则返回保留期内的消息。此接口不改变未读。
- `POST /api/conversations/:id/read`：提交 `messageId`，把该成员的最后阅读编号更新到这条消息
- `POST /api/files`
- `GET /api/files/:id`
- `GET /api/ws`

管理员：

- `POST /api/admin/session`
- `POST /api/admin/logout`
- `POST /api/admin/password`
- `GET /api/admin/stats`
- `GET /api/admin/users?q=`
- `PATCH /api/admin/users/:id`
- `GET /api/admin/groups`
- `DELETE /api/admin/groups/:id`

没有对应 Cookie 的请求拒绝访问。聊天会话不能调用 `/api/admin/`。

## 失败行为

- Key 不合规则：页面直接提示，不发请求
- 登录被限流：提示稍后再试
- 账号被封禁：聊天页显示封禁说明，已有连接收到 `session.revoked` 后断开
- 没有发言权或发文件权：对应控件不可用；已经发出的请求只回传给发送方
- 文件超过大小，或图片消息的 MIME 不是 JPEG、PNG、WebP、GIF，或磁盘写入失败：上传失败，不产生消息。普通文件不限制 MIME
- 下载者不是会话成员：拒绝，不返回文件内容
- 数据库短时锁住：服务端最多重试 3 次，间隔 50 毫秒，仍失败则让发送方重发
- 服务重启：网页自动重连，并从数据库补齐历史

## 测试

Go 测试覆盖：

- Key 校验
- 同一对用户只有一个一对一会话
- 封禁和三项权限会拒绝对应操作
- 非会话成员不能下载文件
- 聊天接口的用户对象不包含别人的 Key，`GET /api/me` 包含自己的 Key
- 超过 48 小时的消息和文件被删除
- 未满 48 小时的消息和文件保留
- 没有 `sl_admin` 时管理接口拒绝访问

界面手工检查：启动打印、Key 登录、修改昵称和头像、一对一文字、发图片、发文件、拖放文件到聊天区、建群并发言、退群、未读数字、离线头像变灰、封禁后连接断开、修改管理员密码后用新密码登录。窄于 960px 时列表和聊天分两屏。

## 第一版不做

- 屏幕共享
- 远程控制
- 全员广播
- 程序内置 HTTPS
- 修改或找回别人的 Key
- 群主踢人、群主转让
