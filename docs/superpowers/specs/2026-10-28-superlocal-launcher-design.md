# SuperLocal 服务管理壳设计

在现有 Go 服务之外增加一个 Electron 壳子。对方电脑双击安装包即可打开管理页，不需要单独安装 Go 或 Node。聊天、图片、文件和 48 小时保留仍由现在的服务器转发，这一版不改成 WebRTC 直连。

## 目标

- macOS 与 Windows 各有一个安装包。
- 双击只打开管理窗口，服务保持停止，直到用户点「启动」。
- 管理页能看到状态、端口、聊天地址、后台地址、管理员账号和密码，并能启动、停止、用系统浏览器打开聊天或后台。
- 关掉窗口后程序留在托盘，服务按当前状态继续。托盘「退出」会先停服务再退出壳子。
- 端口可改，默认 `8080`。

## 不做的事

- 不把文字、在线状态、图片或文件改成 WebRTC，也不做端到端直连传输。
- 不改现有 HTTP API、WebSocket、页面路由和 48 小时清理。
- 打开壳子时不自动启动服务，也不做开机自启。
- 不做 Linux 安装包、代码签名、公证和通用二进制。
- 管理页不提供上传大小设置，服务仍使用 `-max-upload 200MB`。

## 运行形态

壳子是唯一由用户启动的程序。它包含三个部分：

| 部分 | 职责 |
| --- | --- |
| Electron 主进程 | 单实例、托盘、窗口、启动和停止子进程 |
| 本地管理页 | 打包在壳子里的 Vue 页面，服务未启动时也能显示 |
| `superlocal` 子进程 | 现有 Go 服务。macOS 上文件名为 `superlocal`，Windows 上为 `superlocal.exe` |

聊天页和后台用系统浏览器打开，不在壳子里嵌一套聊天界面。

子进程参数：

- `-addr :{port}`，监听所有网卡，`port` 来自管理页
- `-data {userData}/data`
- `-max-upload 200MB`

`userData` 是 Electron 的 `app.getPath('userData')`。数据库、上传文件、头像和 `admin.secret` 都在这个数据目录里，升级安装包不会清掉它们。改端口不搬移、不删除数据目录。

## 目录和接口

壳子放在 `desktop/`。主进程和下面这些模块用 JavaScript，方便 `node --test` 直接运行。管理页用 Vue 3 和 Vite，不使用 Element Plus，也不新增组件库。

| 模块 | 作用 | 对外结果 |
| --- | --- | --- |
| `desktop/src/port.js` | 校验端口 | `1` 到 `65535` 的整数通过；空、`0`、`65536`、小数失败 |
| `desktop/src/banner.js` | 解析服务标准输出 | 聊天地址列表、后台地址列表 |
| `desktop/src/settings.js` | 读写端口 | 端口字段是 `1` 到 `65535` 的整数时返回该值；文件缺失、损坏或端口非法时返回 `8080` |
| `desktop/src/pid.js` | 判断残留进程 | 进程仍在且可执行文件路径等于本次要启动的服务程序时采纳；否则丢弃 |
| `desktop/src/supervisor.js` | 启动、健康检查、停止 | 依赖注入的进程和 HTTP 探测，不直接绑窗口 |

管理页只通过 IPC 跟主进程说话，自己不启动子进程。状态对象包含：

- `status`：`stopped`、`starting`、`running`、`failed`
- `port`
- `error`：要显示的一行说明；没有则是空字符串。端口非法、启动失败或停止失败时会有内容
- `chatUrls`、`adminUrls`
- `username`、`password`
- `secretState`：`hidden`、`ready`、`unreadable`

主进程在状态变化时把这份对象推给页面。页面可以请求当前状态、启动、停止、在服务停止时保存端口、打开聊天、打开后台。

开发时，主进程启动仓库里 `CGO_ENABLED=0 go build -o desktop/binaries/superlocal ./cmd/superlocal` 产出的程序。打包后启动 resources 里的同名程序。

## 窗口和托盘

窗口标题是 SuperLocal。默认宽 420、高 640，可以调整大小，最小 380×520。

双击已在运行的壳子时，只把现有窗口带到前面，不启动第二份壳子，也不启动服务。macOS 上点 Dock 图标同样只显示窗口。

点关闭，窗口隐藏，程序和服务都保持当前状态。macOS 的 Dock 图标仍在。点最小化只缩到任务栏或 Dock。

托盘菜单：

- 显示窗口
- 启动服务或停止服务，文案随状态变化
- 打开聊天
- 打开后台
- 退出

「退出」和 macOS 的退出相同：状态是启动中或运行中时，先按下面的停法结束服务，再退出壳子。

## 管理页

颜色和字体与现有产品一致：主色 `#0B6BCB`，按下 `#0958A8`，页面 `#F3F5F7`，面板 `#FFFFFF`，边框 `#E6E8EB`，正文 `#1F2329`，次要文字 `#646A73`。字体使用 `PingFang SC`、`Microsoft YaHei`、`sans-serif`。正文字号 14px，圆角 8px。失败原因用一行次要文字，不用插图。

从上到下：

- 状态：已停止、启动中、运行中、启动失败
- 端口数字框，默认 `8080`。服务处于启动中或运行中时不能改
- 「启动」和「停止」。已停止或启动失败时只能点启动；启动中或运行中时只能点停止
- 聊天地址和后台地址。旁边是「打开聊天」「打开后台」，只有运行中可点
- 账号和密码，明文显示，可以选择复制

「打开聊天」打开 `http://127.0.0.1:{port}/`，「打开后台」打开 `http://127.0.0.1:{port}/admin`。页面上同时列出服务打印出的局域网地址，给别的机器用。

还没有 `admin.secret` 时，账号和密码显示「启动后显示」。文件存在且能读取时显示其中的两行，即使这次启动失败也显示。文件读失败时，地址照常显示，账号和密码那一行显示「无法读取管理员密码」。

端口记在 `{userData}/launcher.json`，内容是 `{ "port": 8080 }`。合法端口在已停止或启动失败时立即写入；非法输入不覆盖上次保存的值。服务处于启动中或运行中时，保存端口的请求被拒绝。

窗口每次显示，以及状态变为运行中时，重新读取 `admin.secret`。文件须是两行非空文本，第一行是账号，第二行是密码。行数不对或有空行时，`secretState` 为 `unreadable`。

非法端口不启动子进程，`error` 为「请输入 1 到 65535 的端口」。

## 启动和停止

点「启动」且端口合法时，写入 `{userData}/superlocal.pid`，然后拉起服务程序。计时从进程创建成功开始，最长 10 秒。

`http://127.0.0.1:{port}/` 收到任意 HTTP 状态码后，状态改为运行中。地址取自服务标准输出里的 `http://` 行：路径为 `/` 的是聊天地址，路径为 `/admin` 的是后台地址。健康检查已经成功但标准输出里没有这些行时，至少放入本机的聊天地址和后台地址。账号和密码只从 `admin.secret` 读取，不从标准输出取密码。

10 秒内进程退出：状态改为启动失败，`error` 使用标准错误里最后一行非空文本。10 秒内进程仍在但端口没有响应：结束该进程，状态改为启动失败，`error` 为「服务在 10 秒内没有开始监听」。用户在这 10 秒内点了停止或退出时，按停止处理，不再记成启动失败。resources 里找不到服务程序时不创建子进程，`error` 为「找不到服务程序」。

现有服务在开始监听之前就会写入 `admin.secret`。因此端口被占用时，文件可能已经存在，页面仍显示其中的账号和密码。

壳子不自动再次启动服务。

「停止」先请求进程结束，最多等 5 秒。macOS 上先发 SIGTERM，超时后发 SIGKILL。Windows 上先结束进程，超时后强制结束。进程消失后删除 pid 文件，状态改为已停止。强制结束后进程仍在时，状态保持运行中，`error` 为「停止服务失败」。

壳子打开时读取 pid 文件。记录里的进程仍在，且其可执行文件路径与本次要启动的服务程序相同，就把该进程当作当前服务，状态为运行中，「停止」可以关掉它。本机聊天地址和后台地址用已保存的端口组成，局域网地址留空，直到下次由本壳子启动并解析到标准输出。进程已经不在，路径对不上，或读不到路径时，删除这条记录，状态保持已停止，不结束别的程序。

## 打包

使用 electron-builder。

- macOS 在 Mac 上打 `.dmg`，里面是 `.app`，并带上该机构架的 `superlocal`。
- Windows 在 Windows 上打安装程序，并带上 `amd64` 的 `superlocal.exe`。不在 Mac 上交叉打 Windows 安装包。
- 每个安装包只带自己系统的服务程序。服务程序用 `CGO_ENABLED=0` 编译。
- 打包前把二进制放到 `desktop/binaries/`，再放进安装包的 resources。

打安装包的电脑需要 Go 和 Node。Node 版本与现有 `web` 构建相同，本仓库目前用 Node 24。装好的程序在对方电脑上运行时，不要求对方安装 Go 或 Node。macOS 安装包不做签名，对方第一次打开时按系统提示允许该应用。

README 增加一节，说明上述构建命令、两条打包路径，以及对方机器不需要 Go 或 Node。

## 测试

现有服务的 `CGO_ENABLED=0 go test ./...` 保持通过。

`node --test` 覆盖 `port.js`、`banner.js`、`settings.js` 和 `pid.js`：

- 默认端口是 `8080`；`1` 和 `65535` 通过；空、`0`、`65536` 和小数失败
- 从服务打印的文本中取出聊天地址和后台地址，端口与本次启动一致
- 端口写入后再读出仍是该值；文件损坏或端口超出范围时得到 `8080`
- 已退出的进程号被丢弃；可执行文件不是本次服务程序时不采纳

托盘、关窗口和安装包用手工核对：

- 双击只出管理窗口，状态是已停止
- 改成非 `8080` 的端口后启动，系统浏览器能打开聊天和后台，局域网地址带这个端口
- 端口被占用时状态为启动失败，并显示原因
- 关掉窗口后服务仍在，托盘能把窗口叫回来；托盘「退出」后服务进程消失
- 再双击不会启动第二份壳子
- 在后台改掉管理员密码，重新显示管理窗口后出现新密码
- macOS 的 `.dmg` 和 Windows 安装包在没装 Go、Node 的机器上都能完成启动和停止
